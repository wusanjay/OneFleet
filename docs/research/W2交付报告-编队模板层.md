## 二、端到端验证实录

`templates/solo-growth.yaml` 一键导入 → 3 个 Agent（调研员/写手/复盘员，含完整人设）→ 群聊"一人公司增长组"建立 → welcome 任务自动发出 → **调研员干了 3 分 59 秒的真活**：

- 真实联网逐条核验来源（掘金/36氪/腾讯云/人人都是产品经理），剔除了 404 和低可信来源
- 产出 3 个选题角度，全部附可访问链接 + 置信度星级（遵守了模板里的 instructions）
- 标注合规风险（"收入数字在小红书属敏感表述"——遵守了复盘员的合规指令）
- 产出交付文件 `调研_选题角度_AI编队做个人IP.md` 存入资料库
- 自动派发后续任务："@写手 请基于角度一产出初稿；@复盘员 初稿就绪后按验收标准做句子级合规检查"

**这证明了核心论点：编队模板里写的行为约束（附来源、置信度标注、合规口径）真实传导到了 Agent 行为。** 这是"编队模板播放器"这个产品的价值实证。

## 三、过程中发现并解决的四个问题（都是 fork 的必要修复）

1. **`glm-5.3-flash` 不在 zai 精选列表** → 服务器远程目录没有 zai，静态 `CURATED_MODELS` 也只有 glm-5.3/5.2。已把 flash 加入静态精选（编队多轮串行任务本就该默认高速档，注释写明了理由）。
2. **后台 helper 需要 bundled Node runtime** → `node bin/ensure-runtime.cjs --kind node` 下载 v24.17.0 后重启应用即修复。**这条要进发布文档。**
3. **`createCustomAgent` 的 guidance 契约陷阱（最重要）**：`normalizeAgentProfile` 的读取顺序是**外层键优先**，而 create 调用永远带着 `knowhow`/`standards` 两个 undefined 键 → 传在 `profile` 对象内部的列表会被 undefined 遮蔽，静默丢失。修复：导入器改传**顶层** `knowhow`/`standards` 选项，代码注释里记录了案例日期。
4. **环境变量在桌面进程解析**：`api_key_env` 由主进程读取，应用必须带 env 启动（`GLM_API_KEY=... Electron .`）。文档要写清。
