# OneFleet 三栏形态设计讨论稿

**日期：** 2026-10-15
**性质：** 设计讨论（本轮不写代码）
**输入：** 用户飞书截图（OpenClaw 大龙虾跑在飞书里的真实画面）+ Grok Bot / Meta Muse / Manus(Cue) 三路深度调研 + 现有实现盘点
**结论预告：** 采纳用户的三栏提案，给出每栏的完整定义、与现有实现的映射、以及后端影响评估（结论：主进程零改动，renderer 一次中等规模 IA 重构）

---

## 一、三个对标产品各自验证了什么（一句话版）

| 产品 | 形态 | 验证的结论 |
|---|---|---|
| **Grok Bot**（2026，桌面 App） | **侧栏 = Bot 名册**（头像+名字+职位+Pin/Hide/复制），IM 语法（私聊/群聊/handoff/@提及），头像即状态灯（六态动效），模板市场按职能分类 | **“机器人版飞书”已经是被 xAI 押注的成熟形态**，我们不用再论证方向 |
| **Manus Cue**（2026-09-28，独立 App） | 每个 agent 有**身份**（email/电话/钱包/电脑）+ agent 团队群聊 + 接入四个 IM + Playbook 模板画廊 | **“agent 有身份、有群、有模板市场”被 Manus 用独立产品验证**；它的"计划即文档"和"知识提案-审批"是好的任务语法 |
| **Meta Muse**（2026-09，手机优先） | **单会话外壳 + 编队内核**（用户只见一条对话流，subagent 全在后台），审计轨迹分"已完成/计划中"双段，审批按风险分级，人格 = SOUL.md 文件 | 提供了**任务执行 UI 语法**（审批门/审计/主动推进），且证明**多 Agent 编队层是它没做、我们做的空白** |
| **飞书 + OpenClaw**（用户截图） | 图标栏 / 对话列表（bot 与人混排，角色 chip 区分）/ 内容区 | **中文用户心智里的"完美形态"参照**，也是我们目标用户每天在用的东西 |

## 二、现状与目标的差距诊断（对照截图逐项）

| # | 差距 | 现状 | 飞书/Grok Bot 的样子 |
|---|---|---|---|
| 1 | **栏结构** | 两栏：左侧栏（文字按钮+会话混排）+ 主区 | 三栏：图标导航栏（纯系统级）/ 对话列表栏 / 内容区 |
| 2 | **会话行信息密度** | 只有会话名 + 时间，无头像/类型/预览 | 头像 + 名字 + **角色 chip（智能体/机器人/群）** + 预览文本 + 时间 + 未读点 |
| 3 | **中栏的组织维度** | 按时间分组（最近对话/全部对话） | 飞书按类型混排；**Grok Bot 按机器人组织**（会话是一次性的，机器人是持久的） |
| 4 | **机器人"人格感"** | 头像只出现在聊天流里 | Grok Bot：头像=状态灯（Idle/Thinking/Working/Waiting/Blocked/Done 六态动效），列表里每个 bot 都"活着" |
| 5 | **工具入口位置** | 左栏折叠组（工作台） | 飞书：图标栏一级入口，点开后**在内容区展开**（不挤占对话区） |
| 6 | **任务过程的呈现** | 活动面板/执行时间线（日志感） | Manus：步骤叙述 + "它的电脑"实时画面 + 回放；Muse：已完成/计划中双段审计 |
| 7 | **模板/编队的入口** | 一个"导入"按钮 | Grok Bot：Marketplace 按职能分类 + 模板卡（职责+审批边界声明）+ 预览 + 一键实例化 |

## 三、目标形态：OneFleet 三栏方案

### 3.1 左栏 = 图标导航栏（约 72px，图标+小字竖排）

```
[Logo OneFleet]
[🔍 搜索]
[＋ 新建]        ← 点击弹出：新对话 / 导入编队模板 / 新建智能体
[💬 消息]        ← 默认选中
[👥 编队]        ← 编队库（模板网格 + 我的编队），原"导入编队模板"升级
[🤖 智能体]      ← 通讯录（原 AI 团队页）
[⧈ 工作台]       ← 点开后右栏显示工具面板（见 3.4）
      ⋮（底部）
[⚙ 设置]
[🙂 用户头像]
```

对应关系（按用户的映射）：加号新建 / 消息 / 工作台 这些系统级功能 → **全部收进图标栏**。现在的"新对话/导入编队模板/AI 团队"三个文字按钮变成三个图标位，技能库/资料库/连接器/待办/自动化/应用收进"工作台"单图标位。

### 3.2 中栏 = 情境列表栏（约 300px，随左栏选中项切换内容）

**选中"消息"时（默认）**：
- 头部：`消息` 标题 + 分段过滤器（**全部 / 机器人 / 群组**）+ `+`（新建群聊/导入模板）
- 会话行：**头像（智能体头像或编队群头像堆叠）+ 名字 + 类型 chip（编队/机器人）+ 最新消息预览 + 时间 + 未读点**
- 排序：置顶（Pin 的机器人/编队）→ 有未读 → 按活跃时间
- **组织原则采纳 Grok Bot 的主张**：机器人是持久对象，会话是一次性的——机器人私聊行 = 这个机器人本身（Pin 后永远在列表顶部）；编队群行 = 这支编队

**选中"编队"时**：编队库网格（我的编队卡片：成员头像堆 + 成本累计 + 最近活跃；模板卡：职责描述 + 边界声明 + 导入按钮）——W3 的"模板库网格"落在这里。

**选中"智能体"时**：通讯录列表（现有 AI 团队页内容收编为中栏列表，详情进右栏）。

**选中"工作台"时**：中栏显示工具清单（待办/自动化/技能库/连接器/资料库/应用），点击后该项内容进右栏。

### 3.3 右栏 = 内容区（弹性宽度）

两种内容态：
1. **会话态**（默认）：现有聊天流 + composer + 成员面板 + 成本条——全部保留，只需把宽度约束从"全宽"改为"右栏宽"
2. **工具态**：从工作台/编队/智能体点进的功能面板在此展开（带返回会话的常驻方式：左栏"消息"一键回聊天）

### 3.4 消息流的四个强化（本轮讨论的重点补充项）

1. **头像即状态灯**（Grok Bot 六态）：中栏机器人行、群聊成员面板、聊天流里的头像统一加状态环——空闲灰/思考黄/执行绿脉冲/等待橙/受阻红/完成绿，hover 显示一句话当前动作（"正在检索竞品定价页…"）。现有"执行中"文字标签升级为动效。
2. **异构事件卡**：编队运行中的关键事件做成卡片混入消息流——已有基础（"已创建群聊"卡），补齐：✅ 交付物卡（文件+预览）、📋 计划卡（编队开工前产出 Markdown 计划，可编辑后确认——Manus Plan-as-Artifact 模式）、💰 成本里程碑卡（每消耗 10 万 tokens 一张，呼应成本条）。
3. **审批不入群**（Grok Bot 安全边界）：外发/花钱类动作的确认卡走私聊或独立审批抽屉，绝不混进编队群流——这条同时满足合规（智能体新规的"人机协同审核"）。
4. **审计双段**（Muse）：会话信息抽屉（现有右侧 Files 面板）加"已完成 / 计划中"双段——数据源就是现成的 task_board（会话任务板），纯 UI 组织。

## 四、后端影响评估（本轮讨论要求）

| 改动项 | 层 | 影响 |
|---|---|---|
| 三栏布局 / 侧栏重组 / 中栏会话行 | renderer（index.html + style.css + setView） | **纯前端**。主进程零改动 |
| 会话行的类型 chip / 头像 / 预览 | renderer + 现有 IPC（conversations.list 已返回足够元数据；群会话可从 members 缓存取头像堆） | **纯前端**，最多给 conversations.list 加一个轻量字段 |
| 头像状态灯 | renderer；数据源 `state_changed` 事件已在推送（groupBusyConvs / _latestInFlight） | **纯前端** |
| 事件卡（交付物/成本里程碑） | renderer；数据源现成（task_board、usage-ledger IPC 已有） | **纯前端** |
| 计划卡（Plan-as-Artifact） | ⚠️ 唯一涉及约定的项：需要编队开工前让 Commander 先产出计划消息。可以用**模板 schema 加 `plan_required: true` + welcome_task 改为两段式**（先出计划→用户确认→再执行）实现，不改引擎 | **低**：模板层约定，不动 bus |
| 审批抽屉 | 中长期项：涉及权限分级与动作拦截，动 guard 层 | **中**，建议 W5 立项 |
| 模板三层分发（链接/市场/团队版） | 导出器已能产 YAML；分享链接需要轻量静态托管或导入剪贴板 | **低-中**，分阶段 |

**总评：三栏形态 = 纯 renderer IA 重构 + 现有后端能力的重新组织。** bus.ts / 模板层 / 成本账本 / 成员面板全部原样保留。工作量主体在 index.html 的面板布局模型改造（现在 panel 是全屏切换，要改成"左栏固定 + 中栏固定 + 右栏内容容器"），预计 1.5–2 周。

## 五、落地分期建议

| 期 | 内容 | 备注 |
|---|---|---|
| **P1（形态骨架）** | 图标栏 + 中栏会话列表（类型 chip/头像/预览/过滤器）+ 右栏容器化 | 一次 IA 重构到位，之后所有功能都长在新形态里 |
| **P2（人格感）** | 头像状态灯六态 + 事件卡（交付物/成本里程碑）+ 计划卡（模板约定） | 让机器人"活"起来 |
| **P3（编队库）** | 中栏"编队"页：我的编队卡片（成本/成员/活跃）+ 模板网格 | 模板生意的货架 |
| **P4（信任层）** | 审计双段抽屉、审批抽屉、权限档位 | 对齐智能体新规 |
| **P5（远期）** | 三级介入漏斗（状态→预览→接管）、SOUL.md 导出分享 | Grok Bot/Muse 的深水区 |

## 六、需要你拍板的三件事

1. **中栏组织原则**：飞书式"全部会话按时间混排 + 类型 chip"，还是 Grok Bot 式"按机器人组织（机器人持久、会话一次性）"？——我倾向**混排为主 + 支持置顶机器人**（飞书心智对国内用户更零成本，置顶补足 Grok 的"回到同一个机器人"）。
2. **工作台的位置**：图标栏一级入口（点开右栏变工具面板，如 3.4 方案），还是保持现在的折叠抽屉？——我倾向升级为一级图标位，因为"老板自己做些事"是你明确的场景。
3. **P1 的范围确认**：是否同意"P1 只做三栏骨架 + 中栏会话行强化，头像状态灯和事件卡放 P2"？——避免一口气吃成 IA 重构 + 视觉重做同时进行。
