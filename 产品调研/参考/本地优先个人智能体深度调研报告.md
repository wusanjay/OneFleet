## 〇、先给结论（TL;DR）

如果你只读一页，读这一页。

### 1. 赛道判断：风口是真的，但你理解错了一半

**【事实】** 2026 年 7 月到 10 月的四个月内，五大玩家密集入场，全部指向同一个产品范式：

| 时间 | 玩家 | 产品 | 一句话形态 |
|---|---|---|---|
| 2026-08-11 | xAI | **Grok Bot** | 多个 Bot 共享一台云电脑，群聊里互相派活 |
| 2026-09-08 | Meta | **Muse** | 人人可用的个人管家，跑在专属安全 VM 上 |
| 2026-09-28 | Manus | **Cue** | 每个 Agent 有独立邮箱/电话/钱包，可拉群协作 |
| 2026-10（DevDay） | OpenAI | **dots** | 常驻 Agent，自己的云电脑，4000+ 应用插件 |
| 2026-10-21 | Anthropic | **Claude Duet** | 面向职场，晨报 + 主动推送 + 6000+ 连接器 |

**【推断】你的"升维"判断成立，但方向要修正。** 这个品类的本质不是"OpenClaw 多开几个"，而是三个同时发生的转变：

1. **从「对话」转向「目标」**——用户不再逐步下指令，而是给一个长期目标（"把啤酒肚减掉""帮我盯住这 5 个竞品"），Agent 自己拆解、持续推进、主动回报。这是"目标模式"的真正含义。
2. **从「单 Agent」转向「Agent 团队」**——Grok Bot 的 2–6 Bot 群聊、Manus Cue 的独立身份 + 拉群、OpenAI dots 明说"未来让多个 dot 组队"、OpenClaw 的 Sub-agents + ACP。四家都走到了同一处。
3. **从「在你的设备上」转向「给它一台电脑」**——这是最关键的：五家全部把 Agent 放进**云端 VM**。Meta 叫 Muse Secure VM，OpenAI 叫 cloud computer，Anthropic 配独立 VM + 浏览器，xAI 每用户一台共享云电脑。

**第 3 点正是你的机会，也是你的陷阱。**

### 2. 机会：大厂把"本地"这块地主动让出来了

**【事实】** 这不是营销话术，是有书面证据的结构性空白：

- 腾讯 LightVela（云端 Agent 托管，2026-09-26 上线）官方文档明确列出三类"不适合使用的用户"，第一条就是：**"要求完全本地运行、数据不离开终端的用户"**。
- 千问 Go、字节小豆、Meta Muse、Claude Duet 全部是**云端执行**。
- 工信部 NVDB 在 2026-02-05 和 03-11 两次发文提示 OpenClaw 类本地 Agent 的安全风险——**监管默认这类东西会在本地跑，且在规训它，而不是禁止它**。

**【推断】** 大厂不是做不了本地，是**不想做**：本地运行 = 无法收集数据 = 无法形成记忆飞轮 = 无法卖订阅。这是它们的商业模式决定的结构性放弃。而"数据不出设备"对四类人群是刚需：涉密/合规行业、企业内网、有商业机密的小老板、被 AI 厂商数据政策反复伤害过的技术人。

### 3. 陷阱：三件事会杀死这个项目

| 陷阱 | 证据 | 规避 |
|---|---|---|
| **"本地"在 2026 年已不是差异化，是基线** | DeepSeek Harness 已 MIT 开源、可本地跑、任意接模型；OpenClaw 40 万 star；Hermes 8–10 万 star | 你的差异化必须落在**编排质量 + 场景包 + 可审计**，不能落在"我也能本地跑" |
| **生态围墙** | 字节豆包手机助手的 SAEP 协议公示后，**151 个应用声明拒绝被操作**（腾讯系 65 款、阿里系淘宝/支付宝/高德、美团、小红书…） | 别做"替你操作 App"，做**本地文件/代码/知识库/私有数据**——不需要第三方许可的场景 |
| **上游断供 + 成本失控** | 2026-04-04 Anthropic 一刀切断第三方 OAuth，OpenClaw 用户月账单**涨 50 倍**；傅盛自曝每天 100+ 美元"养虾" | 架构必须**模型无关 + 可接本地模型**，且把 token 成本做成产品内的显性功能 |

### 4. 商业路径：先建信用资产，再变现（顺序不能反）

**【事实 + 推断】** 从 OpenClaw 那波风口的完整复盘（第 5 章）提炼出的 ROI 排序：

| 模式 | 月收入量级（可核对锚点） | 可持续 | 你的适配度 |
|---|---|---|---|
| 纯代部署/装机器 | 0.6–1 万，**两周内从 500 元崩到 30 元** | ❌ | 不做 |
| 付费教程（9.9–99 元） | 1 万–8 万 | ❌ 官方一简化即归零 | 不做（污名风险） |
| 知识星球/社群（50 元） | 3.5 万–4.4 万 | ⚠️ 需持续运营 | 做，但只做高价技术社群 |
| API 分销 | 两周 5 万+ | ⚠️ **合规高危** | 不做 |
| 硬件倒卖 | 7 天 200 台 ≈ 80 万 | ⚠️ 随新品回落 | 不做（无供应链） |
| **企业定制交付（5000–8 万/单）** | 2 万–10 万 | ✅ **唯一穿越周期** | **核心收入** |
| **Skills/模板订阅（9.9–99.9 元/月）** | 1 万+/月 | ⚠️ 依附平台 | **现金流** |
| **内容 IP → 商单** | 小红书 20 万粉单条视频 **8 万元** | ⚠️ 依赖平台 | **放大器** |

**【推断】你的最优解是"三轨并行"：**
- **轨道 A（信用）**：开源内核 + 公开 benchmark + 可验证的"数据流向审计"
- **轨道 B（现金流）**：小红书/B站内容 → 高客单企业定制交付 + Skills 包订阅
- **轨道 C（杠杆）**：把轻量包上架大厂平台（WorkBuddy 1% 窗口期）借流量，私域卖完整本地版

### 5. 一句话执行建议

> **不要做"中国的 OpenClaw"，要做"OpenClaw 没做的那一层：在一台本地机器上，让 100 个有身份、有记忆、能拉群协作的数字员工替一个人跑完一整条业务流"。**
> 产品上以 **DeepSeek Harness（Cordis 插件内核）+ Hermes（四层记忆/技能蒸馏）+ Orkas（Commander 编排范式）** 为参考骨架；内容上只打**"一人公司 + 100 个数字员工 + 拉群协作"**这一个视觉锤；变现上先做企业定制，再做订阅，最后才是课程。

## 一、品类定义：什么是"目标模式 Personal Agent"

### 1.1 一句话定义

**【推断】** 目标模式 Personal Agent = **一个长期在线、持有你的目标而非你的指令、在独立计算环境里自主拆解并执行多步任务、只在需要判断时才回来找你、并且能调度其他 Agent 协作完成的常驻智能体。**

把它和相邻品类划清界限：

| 品类 | 触发方式 | 生命周期 | 执行环境 | 记忆 | 代表 |
|---|---|---|---|---|---|
| 聊天助手 | 用户提问 | 单次对话 | 无 | 会话内 | ChatGPT / 元宝 |
| 工作流自动化 | 事件触发 | 流程内 | 云端沙箱 | 无 | Zapier / n8n / 扣子 |
| Coding Agent | 用户指派任务 | 单次任务 | 本地仓库 or 云 | 项目级 | Claude Code / ZCode |
| **Personal Agent（目标模式）** | **目标/偏好** | **常驻，跨会话** | **专属 VM / 本地常驻** | **跨会话长期记忆** | **Muse / dots / Duet / Grok Bot / Cue** |

### 1.2 四个缺一不可的判据

判断一个产品是不是真的进了这个品类，看四条：

1. **常驻（Always-on）**——你关掉 App 它还在跑。OpenAI dots 的原话："A bug appears in Slack, and dots immediately start investigating."；Claude Duet "keeps working even when you step away"。
2. **主动（Proactive）**——它先找你，不是你先找它。Claude Duet 每天早晨发简报；Muse 会在夜间整合信息（"彻夜学习"）。
3. **有自己的电脑（Own computer）**——这是 2026 年最关键的产品设计。五家全部给了 Agent 一台独立 VM。意义在于：任务不会因为你的笔记本合上而中断，且 Agent 的浏览器会话、文件、登录态是它自己的，不是你的。
4. **目标驱动而非指令驱动**——Meta 官方举例：用户告诉 Muse "减掉啤酒肚"或"成为更好的父亲"，Muse 自己制定个性化计划、协调资源、推进执行。

### 1.3 为什么是现在爆发

**【推断】** 三件事在 2026 年下半年同时成熟：

- **模型侧**：长程推理能力到位。Anthropic 明说 Duet 的主动性建立在 Opus 5.5 的长文本记忆与逻辑连贯之上——模型能长时间维持逻辑连贯，Agent 才可能从对话框里走出来。
- **成本侧**：Manus 自研 Cascade 框架把 token 消耗降 23.2%、任务时间降 28.2%、运行成本降 32%。行业共识已经变成"Agent 要更聪明，也必须更便宜"。
- **入口侧**：这是最根本的。Gartner 数据：全球 AI 智能体与助手支出从 2025 年 164.81 亿美元增至 2027 年 654.72 亿美元（约 4 倍）。**一旦用户把邮件、日历、文件、业务系统接进 Agent，产品价值就不再取决于单次回答质量，而取决于它能否长期记住偏好、稳定跑完多步任务**——这意味着用户迁移成本骤增，这是入口级战争。

## 二、五大厂竞品深度剖析

### 2.1 Meta Muse：用"安全 VM + 零门槛"打大众市场

**【事实】**
- **发布**：2026-09-08，美国 18 岁以上，iOS / Android / Muse 网站 / WhatsApp，后续进 Instagram、Facebook、AI 眼镜。
- **模型**：Muse Spark 1.3（Meta 自称"迄今最强模型"，专为真实世界 agentic 工作构建）。
- **架构亮点 —— Muse Secure VM**：每个用户的 Muse 跑在**独立的云端虚拟机**上，Agent 和数据都在里面；VM 上同时跑一个**独立的 Sentinel agent**，与 Muse 在系统层隔离，**Muse 的任何对外网络行为必须经 Sentinel 批准**；凭证存于安全存储，Muse 看不到密码；用户在浏览器里自己输入的密码 Muse 也看不到。
- **能力**：发邮件、订行程、网购、填表单、"谈判"（Meta 原话 negotiate on your behalf）；有公共 API 时**自己构建连接器**；已接入 Google Workspace、Ticketmaster、Spotify、Apple Health、OpenTable。
- **支付**：Stripe 的 Link for Agents，生成一次性卡号隐藏真实卡信息，是首个被 Link 购买保护覆盖的 AI Agent。
- **商业化**：免费版为主，付费档 **$20/月、$100/月**（换取更多算力）；免费额度每周最高 1 亿 token。
- **数据表现**：上线不到 10 天登顶美国 App Store 免费榜，超越 ChatGPT 和 Claude；上线 13 天累计下载约 260 万、美国移动端 DAU 64.2 万；3 周后周活 300 万+、日活 100 万+、累计下载近 900 万。**但 14 日留存 22.5%，低于 ChatGPT 的 26.8%**。
- **负面**：2026-09-20 起被亚马逊封禁访问；09-25 被曝 VM 安全漏洞。

**【推断】对你的意义**：Muse 证明了一件事——**"给 AI 一张脸"比"给 AI 一堆配置项"更能拿下大众市场**（用户可定制 Muse 的外观、名字、服饰）。你的产品在"开箱即用"上必须对齐这个标准，不能因为是本地的就要求用户配环境。同时，Muse 的 22.5% 留存是个警告：**这个品类目前的留存天花板不高，产品必须在一周内让用户看到一次"它真的替我办成了一件事"**。

### 2.2 OpenAI dots：把 Agent 塞进 ChatGPT 的分发红利

**【事实】**
- **模型**：GPT-6 Astra。
- **形态**：dot 是 ChatGPT 内的常驻 Agent，**有自己的云电脑、自己的浏览器**；你可以随时"打开 dot 的电脑"检查它在做什么。
- **连接**：插件生态可连 **4000+ 应用**；可在 ChatGPT / Slack / Teams 里找到它；可发起语音通话。
- **本地接入**：**可选、默认关闭**——授权后 dot 可以连接并使用你的笔记本电脑（创建 Work/Codex 任务、用本地 skills、在云浏览器被拦时用本地浏览器）。
- **多 Agent**："Over time, we envision teams of dots working together on your behalf"——目前先给一个 primary dot，未来是多 dot 团队；已预览"专家 dot"（独立身份、IT 配置的硬件、与企业记录系统深度集成）。
- **分发**：ChatGPT Pro / Business Premium / Enterprise 逐步开放（不含 EEA、瑞士、英国）；**第一个 dot 免费包含在 Pro / Business Premium 套餐内**；首月不计入用量限制。命名后 handle 变为 `@yourname-agentname`。
- **场景**（官方原文）：开发者——盯用户反馈、自动修 bug、提交带演示视频的 PR；产品发布负责人——scope 变更时自动同步改文案和物料；科学家——新数据到达自动重跑分析、更新图表；销售——自动核对需求、搭 POC、更新方案；内容创作者——访谈转写 → 切片 → show notes → 社交文案。

**【推断】对你的意义**：dots 最强的不是技术，是**ChatGPT 的分发**。4000+ 插件生态是本地产品短期内不可能复现的。反过来看，dots 明确做了"连接你的本地电脑"这个可选开关——**这说明 OpenAI 也承认"有些数据必须在本地"**，你的产品可以把自己定位成"那个默认在本地的 dot"，并且和 dots 形成互补而非直接对抗。

### 2.3 Claude Duet：最贴近你目标用户的产品

**【事实】**
- **发布**：2026-10-21（研究预览，候补名单制，先面向美国 Pro / Max 订阅用户）。
- **模型**：Claude Opus 5.5，**配备独立虚拟机和浏览器**，因此用户电脑或手机关机后仍可继续工作。
- **形态**：独立 iOS / Android App + claude.ai 网页端；继承用户 Claude 账户里已有的**记忆、技能和已连接应用**（大幅降低配置成本）。
- **连接**：Claude Marketplace **6000+ 连接器和插件**，覆盖 Gmail、Slack、QuickBooks、Stripe 等。
- **主动性**：每天早晨推送简报（跨已连接应用汇总最重要事项）；全天监控，**只在有事时找你**；用户离线时继续推进。Anthropic 内部案例：Claude Code 负责人 Boris Cherny 散步时口述待办清单交给 Duet。
- **安全**：基于 trustworthy agents 框架；凭证处理沿用 Claude Managed Agents 设计（**从不直接看到密码和登录 token**）；动作由 auto mode classifier 审批；新增专用分类器拦截敏感信息外泄（信用卡号、政府身份证号直接拒绝；健康/财务信息仅在用户明确指示时才放行）；红队 + 外部公司渗透测试 + 公开 bug bounty。
- **定位**：**面向职场专业人士和中小企业主**。Anthropic 自己承认"处理订票等个人事务表现稍逊"，也承认"可能误读对话内容或无法准确判断何为紧急事项"。

**【推断】对你的意义**：Duet 是你**最直接的对标物和威胁**。它选了"职场 + 中小企业主"，正是你设想的 OPC/一人公司人群。它的弱点很清晰——**云端**（数据必须给 Anthropic）、**美国限定 + 候补制**（中国用户拿不到）、**月度订阅消耗额度**（后台检查也扣额度）。这三点恰好是你可以正面打的：本地、中国可用、无额度焦虑（只需自付模型 API）。

### 2.4 Grok Bot：多 Agent 群聊协作做的最激进，安全做的最糙

**【事实】**
- **发布**：2026-08-11 beta（桌面 + iOS），随后安卓（09-02）、Linux。
- **核心机制**：每个 Bot 是一个"always-on teammate"，有角色（销售外联、参谋长、研究、招聘、差旅、费用、Bug 复现…）；**一个用户的所有 Bot 共享一台云电脑**——共享文件、浏览器 cookie、命令行凭证。xAI 文档明确写："不要把不同的 Bot 当作安全边界。"
- **多 Bot 协作**：可以把 **2–6 个 Bot 放进同一个群聊**，它们互相发消息、中途移交任务所有权、直接共享上下文，不需要用户手动搬运。官方例子：参谋长 Bot 从另一个 Bot 上季度的对话里取到上下文，直接回复定价问题，不用等用户。
- **学习机制**："Show a Bot how it's done"——你做一遍流程，Bot 在旁边看，把流程存为 routine，之后自主重复运行。
- **调度**：定时批量。案例：销售 Bot 凌晨 4:39 自动启动，研究客户、按招聘信号和文档流量给联系人打分、起草邮件和 LinkedIn 消息（用用户的语气），次日 3:47 完成 36 封草稿（4 封因近期联系过而跳过），**未经明确批准一封不发**。
- **定价**：不单独售卖，捆绑在订阅里 —— 新用户通过 The X Subscription：**Premium $30/月、Super $100/月、Ultra $200/月**；老 SuperGrok / Cursor 套餐保留访问权；**超出周额度按模型和 token 直接计费，且目前没有 Grok Bot 专属的支出上限**。
- **合规**：**无 SOC 2、ISO 27001、GDPR、HIPAA、FedRAMP 认证**——对受监管行业是硬阻断。

**【推断】对你的意义**：Grok Bot 是**"多 Agent 群聊协作"这个形态做得最完整的参考**，你设想的"拉群让数字员工协作"在它这里已被验证。它的致命伤是"共享一台电脑、共享登录态、不隔离"——**这恰好是本地产品能做得更好的地方**：你可以给每个 Agent 独立的凭证存储、独立的工作目录、独立的权限边界，把"隔离"做成卖点（这正是工信部"六要六不要"里强调的最小化权限与独立网段）。

### 2.5 Manus Cue：给 Agent 一个"身份"，最接近你的产品想象

**【事实】**
- **发布**：2026-09-28，与 Manus 2.0 同发（Manus 于 2026-09-01 恢复独立运营）。
- **核心设计 —— 每个 Agent 一个身份**：在 Cue 里，每个 Agent 拥有**独立的邮箱、电话号码、云电脑和数字钱包**，能以"自己"的身份发消息、接听电话、在预算范围内自主付款。创始人肖弘的表述："一个有独立的手机号、邮箱、支付、电脑和足够'智能'的'东西'，也许可以称之为'人'。"
- **群聊协作**：可以把多个 Agent 拉进同一个群聊，像真实团队一样分工协作。
- **BYOD**：用户可以在 Manus 里使用不同的模型 / API Key（这点和 OpenClaw 的模型无关思路一致）。
- **技术底座**：Manus 2.0 自研 **Cascade 框架**——轻量起步、按需加载专业能力；官方测试：token 消耗 -23.2%、任务完成时间 -28.2%、运行成本 -32%。
- **案例**：替用户接房东谈续租的电话、核对医院账单、等预约空位、检查退款到账。
- **状态**：抢先体验阶段，**需邀请码才能免费使用**。用户反馈的体验断点：已连 Gmail 却默认用自己的邮箱发信（在需要以用户身份对外沟通的场景会造成困扰）。
- **公司**：2026-10-08 完成超 5 亿美元融资（博裕、IDG 领投，腾讯、红杉中国、真格跟投），估值约 **40 亿美元**；ARR 从被 Meta 收购时的约 1 亿美元，到 2026 年 6 月升至 **4–5 亿美元**。Manus 已放出 17 个岗位（全部北京），组建国内产品团队。
- **商业化想象**：不只是订阅费，而是**替用户花钱**——订餐厅、买机票、安排旅行，从交易中抽佣。同赛道的 Instinct 平台年化交易额接近 10 亿美元，超一半来自旅游预订，走"个人用户免费、商家付佣金"的路线。

**【推断】对你的意义**：Cue 是你产品想象的**最接近参照**——"一人公司拥有 100 个数字员工，还能拉群协作"这句话，几乎是 Cue 的中文版描述。**这意味着你的产品概念已被验证，但也意味着你必须在 Cue 的盲区里做差异化。Cue 的盲区有三个**：① 全部在云端（数据在美国服务器上）；② 中国市场产品尚未落地（Manus 今年 1 月曾终止对中国大陆用户的全部服务，本土化团队刚组建）；③ 每个 Agent 一套邮箱/电话/钱包的成本极高，无法真的开到 100 个。**"100 个数字员工"这个数字本身就是你的差异化**——在本地跑、用你自己的模型 key、Agent 之间共享本地文件系统和知识库，边际成本趋近于零，这是云端架构永远做不到的经济学。

### 3.2 三条最关键的判断

**判断一：国内大厂全部选了"云端 + 生态围墙"，没有一家做真正的本地优先。**

**【事实】** 唯一的例外是 DeepSeek Harness（MIT 开源、可本地跑），但它是 **Agent Harness（开发者框架）**，不是面向终端用户的产品。腾讯 LightVela 虽然是托管开源 Hermes 的产品，但**官方文档明确把"要求完全本地运行、数据不离开终端的用户"列为不适合人群**。

**【推断】** 这不是遗漏，是战略选择：本地运行意味着放弃数据回收和订阅计费。所以**"本地优先"在国内至今无人占领**——这正是你产品定位最硬的一块地。

**判断二："跨 App 代办"在中国走不通，生态围墙已经成型。**

**【事实】** 字节豆包手机助手的 SAEP（屏幕自动化操作声明协议）30 天公示期于 2026-10-14 结束，结果是 **151 个应用声明拒绝被操作**：腾讯系 65 款（微信、QQ、王者荣耀、腾讯会议、腾讯视频），阿里系（淘宝、天猫、支付宝、高德、钉钉），以及拼多多、美团、大众点评、小红书、快手、滴滴、DeepSeek、Kimi、千问、元宝、WPS、招商银行、工行等。

**【推断】** 这条对你是重大利好：**它替你排除了一个错误的方向**。不要做"替你操作美团/淘宝/小红书"的 Agent（不仅被围墙挡住，还有逆向协议的封号和刑事风险）。正确的方向是**本地文件、代码、知识库、私有数据、可脚本化的内部系统**——这些不需要任何第三方许可，也是 OpenClaw 真正被长期用户保留下来的价值区（定时任务、移动入口、深度蒸馏）。

**判断三：窗口期约 6–12 个月，且"合规地收款"的通道刚刚打开。**

**【事实 + 推断】** 支持这个判断的三个信号：
1. 国内主流个人 Agent 产品（千问 Go、小豆、灵光）**全部处于邀测/内测，没有一家公布完整定价**——说明都还在 PMF 阶段。
2. 腾讯 WorkBuddy 于 **2026-10-12 静默上线"收入变现"**，内测期平台服务费仅 **1%**，开发者自主定价（官方示例 ¥79）——这是国内个人开发者第一次能在桌面 Agent 生态里合规收到 C 端钱。**1% 是补贴期费率，不是长期契约**，[推断] 窗口大约 6–12 个月。
3. Manus 正在组建国内团队（17 个岗位全在北京），Cue 的国内版尚未落地。

**【推断】你的时间预算**：0–6 个月做出可演示的最小内核并积累内容影响力；6–12 个月完成商业化闭环。**12 个月后，本地这条缝大概率会被某个大厂或拿到融资的创业公司填上。**

### 4.2 逐个拆解

#### OpenClaw：产品形态的教科书

**【事实】** 架构是"渠道入口 + 工具执行 + 自动化"，通过 Gateway 提供安全边界：
- **多渠道**：WhatsApp / Telegram / Discord / Signal / Slack / Teams / iMessage / Google Chat / Matrix / WebChat
- **工具**：Browser / Exec / Web，配合审批与隔离策略
- **自动化**：Cron jobs / Hooks / Webhooks / Gmail Pub/Sub
- **2.0（2026-08-30）**：16,000+ PR、933 名贡献者、569 人首次提交；浏览器 App 重建为一等公民；新增 shared cloud sessions（多人同时观看和协作一个 Agent 会话，首次有了多用户故事）
- **模型无关**：默认使用内置 Pi binary（RPC 模式，per-sender session）；2.x 中**"legacy Claude/Codex/Gemini/Opencode paths 已移除，Pi 是唯一的 coding-agent path"**
- **配置示例**（官方）：`channels.whatsapp.allowFrom`（白名单）、`groups.requireMention`、`/activation always|mention`

**【推断】值得抄的三件事**：① Gateway 作为唯一的安全边界与权限收敛点；② per-sender session（每个对话方一个独立会话，天然隔离）；③ 白名单 + 提及规则作为默认安全姿态。

**【推断】不要抄的三件事**：① 多渠道全支持（国内只有企业微信/飞书/钉钉有官方 API，微信个人号接入是逆向工程，有封号风险）；② 依赖单一厂商的 OAuth（已被 Anthropic 一刀切验证过）；③ 技能市场的完全开放（ClawHub 恶意 Skill 比例高达 12%–36%）。

#### Pi：扩展点最完备的 TS 内核

**【事实】** 由 Mario Zechner（@badlogic）创建，现为 `earendil-works/pi`，npm 包 `@earendil-works/pi-coding-agent`（v0.87.1）。有一份第三方技术尽调（EXP-000）专门对比了三个 runtime 的扩展点完备性，结论是 **Pi 是唯一在全部 7 项判据（C1–C7）上全部 PASS 的 runtime**：

| 判据 | Pi 0.87.1 | Hermes v0.21.4 | OpenClaw 2026.9.6 |
|---|---|---|---|
| 工具调用前决策（allow/deny/modify/redirect） | ✅ | 部分 | 部分 |
| 工具结果替换 | ✅ | 部分（异步委派结果绕过 transform） | 部分（Codex 原生工具无法替换） |
| LLM 调用前干预 | ✅ | ✅ | ✅ |
| 跳过 LLM 轮次（本地决策后继续/停止） | ✅ | ✅ | ✅ |
| 生命周期钩子 | ✅ `before_agent_start` | ✅ | ✅ |
| 终止 / follow-up 控制 | ✅ | ✅ | ✅ |

**【推断】** 如果你要做"能在工具执行前后插入自定义逻辑"的产品（比如：敏感操作二次确认、成本上限熔断、数据出境拦截、审计日志），**Pi 是三个里唯一能干净实现的**。这也是它被 OpenClaw 2.x 选为唯一内核路径的原因。

#### Hermes Agent：记忆与自进化，你最重要的差异化来源

**【事实】** Nous Research 出品，MIT，被称为"世界上使用最广泛的开源 agent harness"之一。**四层记忆架构**：

| 层 | 内容 | 存储/机制 |
|---|---|---|
| **L1 提示词记忆** | `MEMORY.md`（系统对自身的认知：掌握哪些技能、操作规范）+ `USER.md`（用户画像、偏好、常用工作流） | 每次对话启动作为"冻结快照"注入，**主动限制在约 3575 字符** |
| **L2 会话归档与检索** | 历史对话冷数据 | SQLite + **FTS5 全文检索**，按需检索 → LLM 摘要 → 注入（不全量加载） |
| **L3 技能记忆** | 程序性记忆（"怎么做"而非"发生了什么"） | Markdown 技能文件，遵循 `agentskills.io` 标准格式，**支持 auto-patch 迭代** |
| **L4 外部记忆提供者** | 深度用户建模 | 可接 Honcho、Mem0 等 |

**自进化闭环**（五阶段）：
1. **轨迹采集** — 记录工具调用、对话、报错、决策路径
2. **后台复盘** — 任务完成后 fork 出一个**独立的静默子 Agent**，只读模式复盘本次轨迹；判定阈值：工具调用 ≥5 次 / 存在试错 / 执行路径变更，满足任一即判定为高价值轨迹
3. **技能蒸馏** — 把优质轨迹转成标准 Markdown 技能文件（带 YAML 元数据：适用场景、执行步骤、报错预案），存入 `~/.hermes/skills/`
4. **迭代优化** — 技能失败时 `auto_patch_skill` 基于报错日志自动修补，保留迭代记录
5. **复用** — 下次同类任务直接匹配技能，**渐进式披露**（默认只加载摘要，真正执行时再加载完整步骤）

其他：Planner 支持 **Plan → Execute → Replan** 动态循环；40+ 原生工具集；**15+ IM 平台网关**；五层安全（用户授权/操作审批/容器隔离/凭证过滤/注入扫描）；最低 4GB 内存，5 美元 VPS 可跑；核心代码不足 8000 行。

**【推断】这是六件套里最该精读的一个。** 理由：① 你的产品核心卖点"数字员工会越用越懂你"，技术上就靠这套四层记忆 + 技能蒸馏；② 渐进式披露和 FTS5 检索是 token 成本控制的关键——而成本恰恰是 OpenClaw 退潮的第一大原因（用户月账单涨 50 倍、傅盛每天 100+ 美元）；③ "每 15 次工具调用自动复盘"这个设计把学习从"用户主动触发"变成"Agent 的本能"，这是产品体验上的分水岭。

#### Orkas：多 Agent 编排范式，最直接的参考

**【事实】** MIT，本地优先多 Agent 桌面应用（macOS / Windows 安装包，Linux 从源码跑），Node 20+，约 2k stars。**核心设计极其克制且值得抄**：

- **Commander + 9 个内置专家 Agent**（如 DeepResearcher、ContentWriter、PptMaker）
- **Commander 是唯一持有调度工具的行动者**——worker 和 agent 都没有调度权
- **三个调度动词**，这个设计是全项目精华：

| 动词 | 用户看到谁的回复 | 结果是否回到 Commander | Commander 回合 |
|---|---|---|---|
| `hand_off_to({to, message})` | 被委派 Agent 的回复 | 否 | 结束（该回复就是最终答案） |
| `dispatch_to({to, message})` | 被委派 Agent 的回复 | 是 | 继续（Commander 必须说出具体的下一步动作） |
| `run_worker({to, task})` | 看不到（私有输入） | 是 | 继续 |

- **关键约束**：Commander 必须先说出具体的下一步动作，才允许选择 `dispatch_to`；如果剩下的事只是复述 Agent 的回复，规则强制走 `hand_off_to`。**"这一条约束就是阻止多 Agent 聊天以冗余的重复总结收尾的原因。"**
- **并发**：一次响应里发多个 `run_worker` 并发执行；每个会话单个 FIFO runtime，顶层轮次串行
- **可接入外部 CLI coding agent**：Claude Code、Codex、OpenCode、**OpenClaw**、**Hermes-Agent** 都可作为本地会话接入
- **Agent 有私有 skills 和 memory**，随时间改进；数据默认留在本地磁盘，不代理不归档

**【推断】Orkas 的三个调度动词，是你在设计"100 个数字员工拉群协作"时最该直接借鉴的抽象。** 多 Agent 产品最常见的失败模式就是"每个 Agent 都抢着说话，最后 Commander 把大家的话复述一遍"——Orkas 用一条规则解决了它。你的群聊协作如果只抄一件事，抄这个。

#### ⭐ 源码级发现：`src/main/features/group_chat/` 里的四个工程决策

> 以下是本次 clone 源码后直接读到的一手信息（非二手解读），**是全套参考里对你最有价值的部分**——因为 Orkas 是唯一把"多 Agent 群聊"做成生产级代码并开源的项目。

目录：`Orkas/src/main/features/group_chat/`（19,206 行），核心文件：

| 文件 | 行数 | 解决什么问题 |
|---|---|---|
| `bus.ts` | 11,705 | 消息总线与事件流（群聊的心脏） |
| `index.ts` | 1,584 | 模块装配 |
| `state.ts` | 1,288 | 会话与 actor 状态机 |
| `task_board.ts` | 967 | **会话级任务板**（可观测 + 可控） |
| `visibility.ts` | 734 | **每个 actor 的可见消息投影** |
| `router.ts` | 673 | 消息路由（谁该被唤醒） |
| `dispatch_planner.ts` | 214 | 分派规划 |
| `plan_executor.ts` | 208 | 分派执行 |
| `actor-budgets.ts` | 24 | **每个 actor 的预算上限** |

**决策一：每个 Agent 看到的是「自己的历史投影」，不是全量群聊**

`visibility.ts` 里有一个 `GROUP_HISTORY_SOURCE_VERSION`（当前为 8），history source 的构造是：

```ts
`group-main-v${VERSION}:${cid}`                        // Commander 的
`group-main-v${VERSION}:${cid}:actor:${actorId}`       // 每个 agent 各自的
```

**【推断】这是"上下文隔离"真正落地的方式**：群聊是共享的，但**注入到每个 Agent 模型上下文里的历史，是经过可见性规则裁剪后的投影**——不是把所有人的所有话都塞给它。这既省 token（对应 OpenClaw 用户把工具说明从全量发送改成按需发送、token 降 98.5% 的收益），又避免上下文互相污染。

**决策二：任务板是「确定性 host 代码」驱动的，模型没有写板权限**

`task_board.ts` 的注释写得极清楚：

> "It is an OBSERVABILITY + CONTROL entity — every state transition is driven by deterministic host code (routing, the worker loop, turn results, user IPC). **The model has no board-writing tool**; `done` records the execution fact 'the turn ended normally' and `stopped` records a host-bounded termination; **neither is a quality judgement**."

**【推断】这条极其重要，几乎是多 Agent 产品最容易犯的错**：如果让模型自己报告"我完成了"，它会撒谎（这是 LLM 的已知行为）。正确做法是——**完成状态由宿主代码根据"这一轮是否正常结束"来判定，不由模型自评**。而且任务板明确排除三类东西：折叠进活动轮次的 steer 消息、匿名的 `run_worker` 工作、普通工具调用。准入标准是"一个独立的具名 actor 执行"，而不是"谁发起的"。

**决策三：每个 actor 有 per-turn 工具轮次预算**

`actor-budgets.ts`：Commander 与具名 agent 都是 **500 轮**上限，临时 worker 走 schema 默认。注释点明配套机制：**periodic checkpoints（周期检查点）、hard cap（硬上限）、repeat protection（重复保护）、idle watchdogs（空闲看门狗）**。

**【推断】** 这就是"100 个数字员工不会一夜烧掉你一万块"的工程答案。你必须做四件事：轮次上限、周期检查点、重复动作检测（防死循环）、空闲超时。**没有这四件，"100 个 Agent"是一个财务炸弹。**

**决策四：匿名 worker 的工作默认对用户不可见**

`run_worker` 是"commander-turn 的私有实现"——worker 干活的过程，用户看不到，只有结果回到 Commander。三个动词在"用户看到谁的回复"上形成清晰梯度：`hand_off_to`（看到 agent 的回复，回合结束）→ `dispatch_to`（看到，Commander 继续）→ `run_worker`（看不到，只有结果）。

**【推断】这是一个非常好的产品直觉**：100 个数字员工如果每个都往群聊里刷屏，产品就没法用了。**必须默认让大部分工作静默，只在需要人判断时才浮出水面。** 这也正好对应 Claude Duet 的设计哲学——"只在有事时找你"。

#### ZCode：国产生产级 Agent Harness 样本

**【事实】** 智谱 Z.ai 出品，**2026-09-20 开源，Apache-2.0**，5 天 6758 star / 2022 fork。pnpm monorepo，全 TypeScript，Node 24.14.0 + pnpm 10.33.2（mise.toml 锁版本）。

目录结构：`apps/zcode-cli/packages/core`（Runtime 本体）、`bootstrap`（组装启动）、`adapters`（前端/运行环境适配）、`dynamic-workflow`；另有 `packages/desktop`、`packages/web`+`server`、`packages/ui`、`packages/rpc`+`client`（自研 RPC 框架与 Agent 客户端 SDK）、`packages/provider`（模型供应商抽象层）。

**对你最有用的三个设计**：

2. **目标导向长任务管理**——复杂目标被拆解为"规划 → 执行 → 验证"的持续循环，跨步骤保留上下文。
3. **BYOK**——可接任何兼容 Anthropic 或 OpenAI 协议的服务，包括自托管渠道。
4. 支持**微信 / 飞书 / Telegram 遥控** Agent（据评测是国内首个同时打通飞书和微信的编程工具）。

**⚠️ 必须记住的教训**：ZCode 的开源不是计划中的产品决策，而是**信任危机的产物**。2026 年 9 月中旬，用户逆向发现客户端的"代码库索引"功能默认开启，会把本地工作区打包成快照**静默上传到云端 OSS**；媒体 9-21 跟进发酵；智谱随即在 3.14.x 移除整条上传管线，9-20 把源码搬上 GitHub。代价是：开源代码库 + 引入中国信通院和绿盟科技第三方审计 + 全量用户补偿（付费用户 8 张重置卡 + 全体连续 10 天 Token）。

**【推断】这条对你既是警告也是机会**：你的核心卖点是"数据不出设备"，那就**必须在架构上可验证，而不能只是文案**。建议直接把 DeepSeek Harness 的 append-only 会话日志 + Trajectory 视图思路做进去——让用户可以随时审计"这个 Agent 到底往外发了什么"。一旦你被曝"其实上了云"，代价就是 ZCode 的翻版。

#### DeepSeek Harness：插件化最彻底的内核

**【事实】** 2026-08-13 v0.1 开发者预览，MIT，`npx @deepseek-ai/dsh web`（默认 127.0.0.1:3080）。公式是 **Agent = Model + Harness**。

- **Cordis 内核**：管理插件的挂载、卸载和依赖。Cordis services 和 events 让插件互相协作。
- **一切皆插件**：模型、工具、技能、会话、沙箱、存储、循环、调度、UI 全部是可替换插件，**通过配置选择/替换/扩展任何能力，不需要改 Harness 源码**。
- **每次运行可追溯**：模型看到的一切（系统提示、推理、工具调用与结果、subagent 调度、每一次上下文注入）都记在 append-only 会话日志里；Trajectory 视图可按来源检视；**恢复、分叉、检索、回放都基于同一条事件流**。
- **四种运行时模式**：Standard（全工具集）/ Code（PTC，模型生成代码编排多轮工具调用）/ Minimal（只有 shell + 文件编辑器，用于 benchmark）/ Creator（检视运行时、在内存里测试 Cordis 插件、组合出新模式）。
- **v0.2（10 月初）**：新增 Claude Code Mods 兼容层、独立插件管理页（输 npm 包名即装）、文档/表格/PDF 导入。**官方口径：约六成用户在使用第三方插件**。
- **桌面端生态**：`dataelement/dsh-desktop` 15.5K star、`dsh-tauri/deepseek-harness-desktop` 3.4K star（Tauri，8MB 安装包）。

**【推断】** 如果你的产品要长期维护、要让用户自由扩展、要能快速适配新模型——**DSH 的"一切皆插件"是三个内核里架构负债最低的选择**。代价是它目前仍是 developer preview（v0.2.1-alpha），API 会 churn。

#### DS Bot：你的"数字员工团队"长什么样，照这个做

**【事实】** `Fei2411/DeepSeek-Bot`，Apache-2.0，约 2.7–2.9k stars，JS。**它是 DeepSeek Harness 的一个插件**，把自己描述为"a team of long-lived bots"。

- 每个 bot 是**一个 DSH session**，有自己的模型选择、自己的记忆、自己的详情页
- 默认有一个叫 **Chief** 的"主管 bot"，权限很高：管理其他 bot 和群聊，第一次打开时引导你完成设置
- **群聊有一个 admin bot 默认回答你，并委派给其他 bot**——所以你不需要为每个成员的每句话付费
- 可以 `@` 某个 bot 直接指派，也可以引用另一个聊天作为上下文
- Bot 之间可以互相移交工作（handoff notes）
- **按时间 / bot / 模型统计 token 用量**
- 数据全部留在 `~/.dsh`，跑在你自己的模型配额上
- 支持 Docker 部署到 NAS 或常驻 Linux 机器

**【推断】这个插件几乎把你想象中的产品画出来了**：一个 Chief（= 你的"一人公司老板 Agent"）+ 一群 specialist bot + 群聊协作 + 本地存储 + token 计量。**你要做的不是重新发明它，而是把它从"DSH 的一个插件"升级为"一个独立、本地优先、面向中国用户、开箱可用的产品"**——补上它缺的东西：中文场景包、国内 IM 合规接入（企业微信/飞书/钉钉官方 API）、可视化的数据审计面板、以及最重要的"100 个 Agent 的并发与成本治理"。

### 4.3 内核选型建议

**【推断】三个内核的真实权衡：**

### 5.4 五个最赚钱的可复制动作

**✅ 动作一：「教程 → 社群 → 定制」三级火箭（阿凯路径）**
99 元教程（3 天做成，2 周 8 万）→ 100 元付费群（200 人，2 万）→ 高客单定制。
**关键洞察**：教程本身不是终局，是**低成本获客漏斗**。真正赚钱的是把"装不上的人"沉淀成社群，再转化为高客单价服务。**【推断】这是单人可复制路径里 ROI 最高的，总投入约 3 天，总回报 10 万元级。**

**✅ 动作二：绑定具体业务场景的定制交付（李岸路径）**
500 元装机的同行在打价格战，李岸靠"电商自动回复询盘""自媒体自动剪辑发布""外贸竞品监控"拿到 5000–8000 元的单子。**同样的人、同样的框架，差别只在"你卖的是安装，还是解决方案"。**【推断】**这是唯一穿越周期的模式**——因为客户付钱买的是自己的业务 ROI，不是 OpenClaw。

**✅ 动作三：订阅制而非一次性（Jimmy、老唐路径）**
29.9 / 39.9 / 99.9 元月订阅，20 天 400+ 用户，月纯利 1 万+。**按月续费 + 自动更新修 bug** 把一锤子买卖变成持续现金流。

**✅ 动作四：有供应链的人卖硬件**
7 天 200 台、80 万营收。本轮**单笔最大、最实在**的钱，且不需要任何 AI 技术能力——只需要有货。（对你不适用，无供应链。）

**✅ 动作五：1 元引流款（河南 00 后女生路径）**
1 元教程，2 万浏览、近千份，只赚约 1000 元，但**2 万次商品浏览**是极强的私域入口。

### 5.5 六个陷阱（都有证据支撑）

**❌ 陷阱一：纯信息差代装** — 500 元 → 30 元，两周崩盘。**任何"照搬免费教程"的服务，窗口期以天计。**

**❌ 陷阱二：成本结构陷阱（最被低估）**
- 代装费 500 元只是开始。跑复杂任务的 token 消耗是普通对话的**百倍乃至千倍**
- 猎豹创始人傅盛：每天 **100+ 美元**养虾；有用户连跑 10 天花 400 美元
- OpenClaw 2.0 的"自我进化"让同样任务 token 费用**涨了 5 倍**（单次提交从 2 万涨到 8 万 token）
- **约三分之一**的养虾人最终卸载，主因是配置复杂、命令行门槛、每月上百元 token 消耗
- 反向优化案例：某用户把工具说明从"每轮全量发送"改成"按需发送"，每轮从 **10,979 token 降到 162（降幅 98.5%）**

**❌ 陷阱三：上游断供** — Anthropic 一纸政策，整个"用 20 美元订阅跑价值几千美元 token"的经济模型崩塌。**任何建立在他人平台灰色地带的生意，命都在别人手里。**

**❌ 陷阱四：大厂收编** — QClaw 停运、千问办公整合、豆包工作收编。**"套壳一个开源项目"建立的优势会随技术扩散迅速归零。**

**❌ 陷阱五：法律红线** — 工信部 NVDB 于 2026-03-31 专门提示**仿冒 OpenClaw 下载网站与安装文件**（公布了仿冒域名和恶意安装包文件名）。这意味着代装链条中传播非官方安装包，**可能直接触及提供非法控制计算机工具 / 传播恶意程序的刑事风险**。

**❌ 陷阱六：内容付费的"同一批人"** — 界面新闻指出，从 ChatGPT、Sora、DeepSeek、Manus 到 OpenClaw，"不同课程背后活跃的经常是同一批人……甚至直接拿过去的课包改个名就上架"。这是纯粹的 FOMO 收割，声誉风险极高。

### 5.6 安全与合规：这节的证据最扎实，也最该被重视

**官方监管动作**
1. **2026-02-05** 工信部 NVDB 预警：OpenClaw 部署时"信任边界模糊"，具备持续运行、自主决策、调用系统和外部资源的特性，**在缺乏有效权限控制、审计机制和安全加固的情况下，可能因指令诱导、配置缺陷或被恶意接管，执行越权操作**；点名 ClawHub 存在恶意投毒风险。
2. **2026-03-11** NVDB《"六要六不要"》，按三大场景分列：
   - 智能办公：供应链攻击 + 内网渗透 → **独立网段、最小化权限、留存完整日志以满足审计合规**
   - 开发运维：**禁止生产环境直接部署、禁止授予管理员权限、建立高危命令黑名单**
   - 个人助手：禁止访问敏感目录、禁止高危操作或加二次确认
3. **2026-03-31** NVDB 仿冒下载站预警（公布仿冒域名与恶意安装包）。
4. Google、Anthropic、Meta 已内部封禁 OpenClaw；三星、SK 等韩国公司发布正式禁令。

**安全数据（英文研究机构）**
- ClawHub 审计：**2857 个 Skill 中 341 个恶意**（335 个属 "ClawHavoc" 攻击行动）；另有口径为 1184 个；安天 CERT 口径 1120 个；单一上传者发布 677 个包
- Snyk：ClawHub **36% 的技能含提示词注入攻击**
- STRIKE：**超 4 万个 OpenClaw 实例暴露公网，63% 存在可利用漏洞，超 1.2 万个可远程控制**；媒体称被扫出的"裸奔"实例高达 27 万

**【推断】对你最直接的结论**：**"本地 + 数据安全"是卖点，也是责任。** 你必须：① 默认不暴露公网、默认最小权限；② 提供可审计的日志（这是 ZCode 用惨痛代价换来的教训）；③ 绝不做 API 倒卖和逆向协议接入微信个人号。

**【事实】可核实的 OPC 收入样本**（2026 上海全球开发者先锋大会）：
- 前设计师**徐爽**：AI 辅助编程做商品视频自动生成服务，"最近几个月平均月收入 1 万–5 万，大多时候稳定在 2–3 万"

**【推断】中国 OPC 的真实分布是两极**：一端是"月入 1–5 万的手艺人型"（可核实），另一端是媒体渲染的"月入百万"（不可核实）。**中间层（月入 10–50 万）几乎没有可公开核对的样本**——这恰恰说明它稀缺。

**【事实】腾讯研究院《超级个体时代》（2026-06-03，3 万字）**：
- 核心公式：**组织竞争力 = 人才密度 × AI 杠杆 ÷ 组织摩擦**（乘除关系，分母减半等价于分子翻倍）
- 超级个体四特征：AI First 工作动线 / 产出 10 倍+ 的量级跃迁 / 极强主动性 / **影响力溢出**（判定阈值：用了 AI 但同事毫无察觉，只是"使用 AI 的优秀员工"）
- **但报告用一整章论证"超级个体为什么还需要团队"，给出一人公司跨不过去的四道墙**：
  1. **风险** — 有联合创始人的公司 5 年存活率高约 45%、获 VC 概率约 1.8 倍、到 PMF 快约 25%；十亿美元级公司约 80% 有 2+ 联合创始人
  2. **注意力** — 能做的事变多，但注意力没扩容
  3. **信用** — **客户认的是组织，不是个人**
  4. **更大的价值场景** — 需要复数的人同时在场

**【推断】这份由大厂智库撰写却用一整章唱衰"一人公司"的报告，是最值得信的。** 对你的含义：**OPC 应被设计成"可持续的小"，而不是"通往大的过渡态"。** 破"信用"这堵墙的唯一方式是**把信用产品化**：开源仓库的 star 数、可验证的 benchmark、公开的客户案例、可试用的 Demo。**这解释了为什么 OpenClaw 的路径是"开源 → 影响力 → 被招安"，而不是"先卖钱"。**

### 6.6 时间分配与必须外包的环节

**【推断】稳定期的配置建议：**

| 环节 | 时间占比 | 瓶颈 | 必须外包 / AI 替代 |
|---|---|---|---|
| 产品（研发 + 迭代） | **40%** | 一人维护多 Agent 编排 + 跨平台兼容 | 测试、CI/CD、文档生成、issue 初筛 → AI；UI 设计 → 一次性外包 |
| 内容（IP） | **25%** | 断更即掉粉 | 选题调研、初稿、剪辑、字幕 → AI；**观点与人格必须本人** |
| 销售（获客 + 成交 + 交付） | **25%** | 最容易被产品挤掉 | 客服 FAQ、onboarding、合同模板 → AI + 工具；**企业交付必须外包或拒单** |
| 运营 / 财务 / 合规 | **10%** | 最容易踩坑 | 记账报税 → 代账公司 |

**【推断】真正的瓶颈不是时间，是"信用"。** OPC 破墙的方式是把信用产品化（开源 star、benchmark、客户案例、Demo）。

### 6.7 合规硬约束

**【事实】主体选择：**

| | 个体工商户 | 个人独资 | **一人有限责任公司（OPC）** |
|---|---|---|---|
| 法人资格 | 无 | 无 | **有** |
| 责任 | 无限 | 无限 | **以认缴出资额为限** |
| 企业所得税 | 不缴 | 不缴 | **缴** |
| 个人所得税 | 经营所得 5%–35% | 同左 | 工资薪金 3%–45%；股息红利 20% |

**【事实】最狠的一条**：「对于只有一个股东的公司，**股东不能证明公司财产独立于个人财产的，应对公司债务承担连带责任**」——**公私混同 = 有限责任保护失效**。必须做到：账户隔离、凭证留痕、规范计税、年度审计。

**【事实】其他红线**：AI 生成内容必须按《生成式人工智能服务管理暂行办法》添加显式/隐式标识；不得搬运模板/资料包；法律/财务/医疗/投资类交付必须人工复核 + 免责声明；接企业单时客户数据不得上传无关第三方，须遵守《数据安全法》《个人信息保护法》；**不得发布荐股、承诺收益类内容**。

**【推断】操作建议**：先个体户/个人独资低成本试错，**跑通月流水 ≥3 万再升级为一人有限责任公司**；但**一旦开始做企业私有化部署，必须升级为公司主体**（企业客户无法与个人签采购合同、无法开专票）。

### 7.6 "100 个数字员工"的技术经济学（这是你最锋利的一刀）

| | 云端方案（Cue / dots / Duet） | 你的本地方案 |
|---|---|---|
| 每个 Agent 的成本 | Cue：独立邮箱 + 电话 + 云电脑 + 钱包（**真金白银的订阅和号码费**） | 一个目录 + 一份记忆文件 + 共享本机算力 |

## 七之二、补充章节（2026-10-24 追加）

> 以下为第二轮源码调研的结论，用于修正本报告的原始判断并补充两个核心设计：记忆分层、员工/模板二元模型。

### 7.7 ⚠️ 更正：微信已经有官方通道，但它锁死了协作形态

**本报告第 7.3 / 7.4 / 第九章原写「微信个人号 = 逆向协议，坚决不做」，此判断错误，现更正。**

**【事实】** 2026-03-22 微信推出官方 **ClawBot 插件**，基于腾讯 **iLink Bot API**，npm 包 `@tencent-weixin/openclaw-weixin`（**微信团队官方发布，MIT 协议**）。这是微信史上首次官方开放个人号机器人接入。Hermes 的网关向导里 `WeChat (ilink / ClawBot)` 走的是同一套。

- **接入**：`openclaw channels login --channel openclaw-weixin` → 扫码授权，无需公网 IP
- **技术**：长轮询 `getUpdates`（35s 超时）+ `sendMessage` HTTP JSON API + CDN AES-128-ECB 加密 + `context_token` 维持会话；内置配对鉴权（Pairing）、同步游标持久化、指数退避、Typing 状态
- **能力**：文本 / 图片 / 语音 / 视频 / 文件全类型收发；内置流式 Markdown 过滤（据说服不支持渲染）

**【事实】但四条限制对"多数字员工群聊协作"是致命的：**

| 限制 | 后果 |
|---|---|
| **iLink 不推送群消息事件** | **群聊基本不可用**（多个信源同一口径） |
| 机器人是独立 iLink Bot 身份（`xxx@im.bot`） | 不是你的微信号，是被塞进聊天列表的新联系人 |
| 同一微信号同一时刻只能对接一个 AI | 绑过 OpenClaw 再绑 Hermes 会自动解绑前者 |
| 能否接收他人消息 | **信源冲突**：一派称"仅自己可用、他人无法添加"，一派称支持收发 + 配对白名单 —— **建议实测确认** |

**【推断】产品结论（这条直接改写了 L5 交互层设计）：**

> **微信 = 遥控器，办公室在别处。**
> 微信只能承载「你 ⇄ 你的 Boss Agent」单聊（下发指令、收结果、收简报）；真正的多员工群聊协作必须在**本地 Web 控制台 / 飞书 / 企微**里做——后两者可以无限创建机器人。
> 这个分工其实不坏，而且符合真实心智：**老板在微信里遥控，员工们在办公室里干活。**

### 7.8 记忆设计：横向对比与四层方案

**【事实】六个项目的记忆单位（源码核实）：**

| 项目 | 记忆单位 | 隔离机制 | 整合 / 进化 | 全局层 |
|---|---|---|---|---|
| **ZCode** | `(workspacePath, agentId)` 二元组 | 项目目录 + 敏感路径黑名单 | ✅ **Dream**（见下） | ⚠️ 接口有 `getUserMemoryDirectory()`，实现未落地 |
| **Hermes** | **Profile（HERMES_HOME）× 四层** | ContextVar + caller_scope 拒绝制 | ✅ Background Review + 技能蒸馏 | ❌ 每个 profile 各自一套，无跨 profile 组织层 |
| **Orkas** | 每 agent 私有 skills + memory | 进程/目录 + **可见性投影** | — | — |
| **OpenClaw** | per-sender session + 工作区 | Gateway + `allowFrom` 白名单 | — | 工作区级 |
| **DSH** | session（append-only log） | 插件化 storage | 由插件决定 | 理论上可借 storage 插件实现 |
| **DS Bot** | 每个 bot 一个 session + 自己的 memory | bot 隔离 | ❌ | Chief 有全局视野，但未做成记忆层 |

**【推断】没有一家做对了 OPC 需要的分层 —— 但拼图是全的**：ZCode 给了整合与冲突消解，Hermes 给了隔离与失败模式，Orkas 给了可见性投影，DS Bot 给了 Chief 视角。

#### 建议的四层方案

| 层 | 内容 | 可见范围 | 写入权 |
|---|---|---|---|
| **L0 组织层** | 我是谁 · 公司业务 · 客户名单 · 财务规则 · 品牌禁忌 | 全部（按权限下发） | **仅 Owner**，Agent 只读 + 建议写（需审批） |
| **L1 角色层** | 岗位 JD + 该员工沉淀的经验与踩过的坑 | 该员工独占 | 员工自己 + Owner |
| **L2 项目层** | 客户上下文 · 项目决策记录 · 共享素材库 | 被授权的员工 | 参与者 |
| **L3 会话层** | 当前对话 + 任务状态 | 本次任务 | 宿主代码判定，非模型自评 |

**两条铁律：**
1. **默认隔离，显式共享** —— 想跨员工/跨层共享，必须"显式发布"到 L2 共享区，不能直接串。
2. **冲突时只标注，交给人裁决** —— 学 ZCode Dream：**当记忆与既有规则冲突时，禁止 Agent 自动改写规则**，只标注 `contradicts <规则> — verify which is current` 并在 summary 里列出。

#### 两个必须抄的实现细节

**① ZCode 的 Dream（`core/src/memory/dream.ts`，239 行）—— 最被低估的部分**
- 24h 最小整合间隔 + 10min 扫描节流 + `.consolidate-lock` 锁 + PID 存活检测
- 处理「记忆 vs CLAUDE.md 冲突」的三条规则：记忆过期 → 删/改写；CLAUDE.md 可能过期 → **dream 期间禁止改 CLAUDE.md**，只标注并列入 summary；不冲突 → 保留
- 整合 agent 的工具被锁死为「只读命令 + 只能删 memory 目录内的 `.md`」
- `SENSITIVE_MEMORY_PATH_SEGMENTS` 黑名单：禁止记忆文件落到 `.git` / `node_modules` / `.zcode` / `skills` / `commands` / `agents`
- **OPC 版映射**：把 CLAUDE.md 换成「L0 组织层规则」

**② Hermes 的 caller_scope（`memory_caller_scope.py`，154 行）—— 抄它的教训**
`memory_provider.py` 第 21 行承认了真实失败模式：

> "…a worker started with an empty context **silently lands on the default profile**"

多员工记忆隔离最大的坑是**静默串号**——张三读到李四的客户档案，你永远不会知道。`memory_caller_scope.py` 存在的意义就是把这个漏洞改成：
- 多路复用进程里**未显式指名 profile 的调用直接拒绝**（不是降级到默认）
- 一个 provider 实例只能服务一个 profile（弱引用表 + `claim_instance`），插件把同一实例塞给多个 agent，第二个起全拒
- `in_owner_home()` 保证后台 worker 在拥有者的 home 下运行，不依赖提交者上下文

> **架构第一原则：Fail closed，不 fail silent。**

### 7.9 「拟人员工」vs「智能体」：模板—实例二元论

**【推断】不需要二选一 —— 正确的模型是「模板 × 实例化」，这也是全行业方向：**
- OpenAI specialist dots：*"their own identity for access management, IT-provisioned hardware"*
- Anthropic：*"Claude Managed Agents"*
- Manus Cue：每个 Agent 独立邮箱 + 电话 + 钱包 + 云电脑

**HR 类比（最准确的心智模型）：**

```
岗位 JD  = 模板：职责 · 能力包 · 工具权限 · 模型偏好 · 预算上限
             ↓ 无记忆 · 无状态 · 可被实例化 N 次
李小     = 员工：名字 · 人格 · 工位目录 · 私有记忆 · 独立成本账
             ↓
发送消息 = 会话
             ↓
工单     = 任务（状态由宿主代码判定，非模型自评）
```

**三条设计原则：**

1. **记忆挂在实例上，不挂在模板上。** 改模板影响所有实例会很糟；员工积累的经验也不该污染模板。
2. **"100 个数字员工" = 「1 个模板 × N 组参数」，不是「写 100 个 prompt」。** 销售模板 × 100 个客户 = 100 个各自记住不同客户的销售专员。**这在云端是成本灾难（Cue 每个 Agent 一台云电脑），在本地几乎零成本** —— 这是本地架构最锋利的一刀。
3. **前台只暴露"员工"，"智能体"退到后台成为能力包。** 就像你不会跟同事介绍"我们公司有 3 个数据分析岗"，你会说"小李负责数据分析"——但 HR 系统里岗位确实得存在。用户面对的是人名和群聊，配置面板里才是模板和参数。

### 7.10 Hermes 的任务执行协调：不在群聊里，在 Kanban Dispatcher 里

**【推断】拟人化群聊是 Hermes 的表象，真正的协调层跟"聊天"无关。**

**【事实】** 协调层在 `HERMES_KANBAN_*` 这套环境变量里：`TASK` / `RUN_ID` / `CLAIM_LOCK` / **`GOAL_MODE`** / **`GOAL_MAX_TURNS`**（后两个说明它有目标驱动模式）。配套 `plugins/kanban` 插件、`kanban_stop.py`、`kanban_turn_recovery.py`。

工程细节（`delegation_context.py`，184 行）：
- **防"子任务升格"**：`scrub_kanban_env` 剥掉子进程的所有 KANBAN 身份键。注释原文：*"TASK absence alone would promote a descendant to an orchestrator"*
- **围栏**：`kanban_path_is_fenced` 实现 *"workers physically cannot see other boards"*
- **会话身份隔离**：`delegated_child_context` 用 ContextVar 隔离子任务的 session id

**【推断】三个真问题：**
1. **隔离是协作式的，不是强制的** —— 源码自承：*"This is cooperative runtime scoping, **not confinement** of code with direct SQLite access"*
2. **拟人化群聊和 Kanban 是两套东西** —— 群里看到的"张三回复了李四"是表演层，真正干活的是看板上的 worker，两者不同步时行为会很怪
3. **没有 token/可见性治理** —— 缺 Orkas 那套"每个 agent 注入裁剪后的历史投影"，多 bot 一上规模上下文成本会失控

**【推断】正确做法**：用 **Orkas 的可见性投影做成本治理** + **Hermes 的 Kanban 做调度**，焊接在同一个壳里 —— 而不是只抄其中一个。
